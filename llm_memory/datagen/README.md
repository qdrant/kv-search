# Data Generation

This subpackage builds the training data of the tower and reader, and the Qdrant evaluation questions. It is ported
from the research scripts. Prompts, parsing, filtering, and file formats are unchanged, so the released data and
checkpoints match this code.

## Pipeline

| Step | Module | Output | Research script |
|---|---|---|---|
| 1. Documents | `corpus fetch`, `corpus build` | `docs.jsonl`: id, kind, source, title, text | `data114_docs.py` |
| 2. Documents for facts | `corpus subset` | `docs-facts.jsonl` | ad hoc, same sampling |
| 3. Topic neighbors (training only) | `neighbors` | `neighbors.json`: hard distractors | `data114_neighbors.py` |
| 4. Facts | `facts` | statement, verbatim anchor and its position, value | `gen114_facts.py` |
| 5. Questions | `questions` | single, multi, abstract, absent, and far questions with anchors | `gen118_questions.py --v2 --far 24` |
| 6. Verification | `verify` | a `verify` object on every question, `keep` = correct and self-contained | `gen124_verify.py` |

Paths follow `llm_memory.train` and `llm_memory.evaluate`:

- `data/train/` holds the training data (`data/src123` in the research repo).
- `data/` holds the Qdrant corpus and its evaluation questions (`data/qdrant123`).

Step 3 runs a local model (Qwen2.5-1.5B-Instruct) on a GPU. Steps 4 to 6 call an OpenAI-compatible server, served under
the model name `qwen`. Each document or fact group is its own async session, so keep the server batch large.

Beyond the package requirements, install `openai` for steps 4 to 6, `pyarrow` for building the training corpus, and
`vllm` on the machine that serves the generator.

## Generator Models

All released data was generated by **Qwen3-30B-A3B-Instruct-2507, AWQ 4-bit** (the `stelterlab` AWQ checkpoint)
served by vLLM, with thinking off and these sampling settings:

- facts: temperature 0, 24 known facts, up to 2000 output tokens;
- questions: temperature 0.3;
- verification: temperature 0.

| Data | Facts | Questions | Verification |
|---|---|---|---|
| `data/train` | 30B AWQ, one server per RTX 3090 (`--part 0/1/2` and `1/2/2`) | 30B AWQ | Only the held-out documents (30B AWQ). Training used unverified questions, see below. |
| `data` (Qdrant) | 30B AWQ: 389 of 444 documents on an RTX 3090, the rest on an H100 | 30B AWQ (H100) | 30B AWQ (H100) |

Qwen3.5-4B (facts) and Qwen3.5-9B (questions) generated an earlier dataset of the research repo, used for the first
retriever. None of it is in the released data.

To serve the generator:

```bash
vllm serve stelterlab/Qwen3-30B-A3B-Instruct-2507-AWQ --served-model-name qwen --port 8000 --max-model-len 8192 \
    --max-num-seqs 96 --gpu-memory-utilization 0.94 --enable-prefix-caching
```

## Training Data (`data/train`, Research `data/src123`)

```bash
python -m llm_memory.datagen.corpus fetch --corpus train --src data/sources/train
python -m llm_memory.datagen.corpus build --src data/sources/train --skip-generated --id-start 500000 \
    --out data/train/docs.jsonl
python -m llm_memory.datagen.corpus subset --docs data/train/docs.jsonl --out data/train/docs-facts.jsonl
python -m llm_memory.datagen.neighbors --docs data/train/docs.jsonl --out data/train/neighbors.json
python -m llm_memory.datagen.facts --server http://127.0.0.1:8000/v1 --part 0/1/2 \
    --docs data/train/docs-facts.jsonl --out data/train/facts-0.jsonl
python -m llm_memory.datagen.facts --server http://127.0.0.1:8001/v1 --part 1/2/2 \
    --docs data/train/docs-facts.jsonl --out data/train/facts-1.jsonl
python -m llm_memory.datagen.questions --facts data/train/facts-0.jsonl,data/train/facts-1.jsonl \
    --out data/train/questions.jsonl
```

The released checkpoint was trained on `questions.jsonl` without verification. The first verification run of the
training set parsed the verifier's JSON object as an array and dropped every answer. After the fix (`verify.py` has
it), only the 678 question groups of held-out documents were verified, for evaluation.

The held-out split is the same everywhere: documents with `md5(id) % 1000 < 50`. Question groups carry it as
`split: held`.

## Qdrant Corpus and Evaluation Questions (`data/`, Research `data/qdrant123`)

```bash
python -m llm_memory.datagen.corpus fetch --corpus qdrant --src data/sources/qdrant --before 2026-10-03T00:35:00Z
python -m llm_memory.datagen.corpus build --src data/sources/qdrant --only repos --keep-qdrant --per-repo 0 \
    --id-start 300000 --out data/docs.jsonl
python -m llm_memory.datagen.corpus subset --docs data/docs.jsonl --out data/docs-facts.jsonl --quota qdrant --seed 124
python -m llm_memory.datagen.facts --docs data/docs-facts.jsonl --out data/facts.jsonl
python -m llm_memory.datagen.questions --facts data/facts.jsonl --out data/questions.jsonl
python -m llm_memory.datagen.verify --questions data/questions.jsonl --docs data/docs.jsonl --out data/questions-v.jsonl
python -m llm_memory.evaluate episodes --questions data/questions-v.jsonl --docs data/docs.jsonl --out data/eval
```

The sources are pinned to these commits:

- `qdrant/qdrant` 6ab21ca;
- `qdrant/qdrant-client` cf747f4;
- `qdrant/landing_page` bb7f15b, whose `documentation` and `articles` content folders are used.

## Sizes of the Released Data

| | Documents | Facts | Questions |
|---|---|---|---|
| Training | 10,811 documents, 26.2M Qwen3 tokens: wiki 2,400, news 1,199, squad 150, code 5,348, docs 1,714 | 428,858 facts over 6,006 documents; 402,113 have a found anchor | 93,293 in 14,279 groups: single 37,853, multi 24,190, abstract 12,864, absent 14,248, far 4,138 |
| Qdrant | 4,856 files, 6.73M tokens | over 444 documents (the 500-document subset without test files) | `evaluate episodes` turns the kept single and multi questions into 1,153 episodes over 354 documents; the results in the main README use 400 of them |

The training corpus has 558 held-out documents. Neighbors: 8 per document.

## Reproducibility

- **Generated text will differ on a rerun.** Questions are sampled at temperature 0.3, and greedy decoding on a batching
  GPU server is not bit-exact either. A rerun gives different facts and questions, so the released files are the
  reference.
- **Document ids depend on the file system.** `build` lists repository files with `os.walk`, whose order depends on
  the file system, and then samples with a seeded RNG. A rebuild on another machine therefore numbers documents
  differently. For repositories with more than 400 files, it also samples different files.
  - The Qdrant corpus takes every file. A rebuild at the pinned commits reproduced all 4,856 released documents (same
    title, kind, source, and text) but with different ids.
  - Facts and questions refer to documents by id, so they match only the released `docs.jsonl`. Run `subset` on the
    released file to get the same documents.
- **Training sources were cloned with `--depth 1`.**
  - The first 17 repositories (including the CPython docs): 2026-10-02, finished by 15:28 UTC.
  - The 12 C++ repositories: 2026-10-02 at about 22:51 UTC.
  - Use `--before` to approach those states.
- **One quirk is kept.** The list of excluded SQuAD articles comes from an earlier experiment. Its multi-word titles
  never match SQuAD's underscored titles.
